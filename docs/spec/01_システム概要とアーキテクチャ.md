# 01 システム概要とアーキテクチャ

## 1. 目的

社員ごとの有給休暇について、次を一元管理する。

1. **付与**：入社日・勤続月数・週勤務日数から付与日数を決定し、付与レコードを登録する
2. **消化**：取得日を登録し、付与レコードの残日数を減らす（先入れ先出し）
3. **失効**：有効期限を過ぎた付与を自動的に失効させる
4. **集計**：社員別・期間別に付与・消化・残・消化率を表示する
5. **申請受理**：勤怠アプリ（MAT）から届いた有給希望を管理者が受理／却下する。受理すると消化が自動登録される
6. **CSVインポート**：過去の付与履歴・消化履歴を一括登録する
7. **テストデータ削除**：検証用に登録したデータを削除する

## 2. 基本情報

| 項目 | 内容 |
|---|---|

| バージョン | 1.2.0（`PL_VERSION`） |

## 3. 管理画面メニュー

トップメニュー「有給管理」（アイコン：やしの木、メニュー位置 31）。

| メニュー | スラッグ | 必要権限 | 概要 |
|---|---|---|---|
| 従業員一覧 | `paid-leave-manager` | `access_custom_plugins` | 全在籍社員の残日数・今年の消化・失効予告・申請件数 |
| 付与・消化登録 | `pl-grant-register` | `access_custom_plugins` | 社員を検索し、付与・消化を登録（登録操作は `edit_custom_plugins`） |
| 集計表 | `pl-summary` | `access_custom_plugins` | 期間・方式を指定した集計 |
| 有給ルール設定 | `pl-rules` | `manage_custom_plugin_settings` | 付与日数マトリクス・有効期限・休日設定 |
| テストデータ削除 | `pl-data-reset` | `manage_custom_plugin_settings` | 付与・消化・申請ログの物理削除 |
| 有給インポート | `pl-import` | `access_custom_plugins`（本実行は `edit_custom_plugins`） | CSV 取込（付与／消化の2タブ） |
| 有給申請管理 | `pl-requests` | `access_custom_plugins` | **現在は非表示**（`PL_SHOW_REQUESTS_PAGE = false`） |
| 個人管理 | `pl-employee-detail` | `access_custom_plugins` | メニュー非表示。一覧の「詳細」ボタン等からのみ到達（`?code=社員コード`） |

> 権限（ケイパビリティ）`access_custom_plugins` / `edit_custom_plugins` / `manage_custom_plugin_settings` は、このプラグイン自身は定義していない。ロール管理側（別プラグイン・別機能）で付与される前提。
> 意味合い：閲覧＝`access_`、登録・変更＝`edit_`、設定・削除＝`manage_`。

## 5. 処理の流れ（全体像）

```
[内閣府CSV] ──(手動/Cron)──> 祝日テーブル ─┐
                                          ├─> 消化・申請時の休日チェック
[ルール設定画面] ──> ルール/設定テーブル ──┘
        │
        ▼
[employee-manager]  入社日・週勤務日数
        │
        ▼
 付与判定(勤続月数→マイルストーン→日数)
        │ 管理者が「付与する」
        ▼
   付与テーブル ──(消化時に残日数を減算)──> 消化テーブル
        ▲                                   ▲
 CSV付与インポート                   単日登録 / 期間一括 / 申請の受理 / CSV消化インポート
        ▲
[MAT] 有給希望 ──> 申請テーブル(pending) ──管理者が受理──> 消化登録
```

## 6. 画面表示のたびに動く自動処理

- **失効処理**：有給管理の画面（`page=paid-leave-manager` または `pl-` で始まるページ）を開くたびに `PL_Grant::expire_old_grants()` が走り、有効期限を過ぎた付与を失効（`is_expired=1`、`remaining_days=0`）にする。実行にはユーザーが `edit_custom_plugins` 権限を持つ必要がある。
- **DBマイグレーション**：`plugins_loaded` で保存済み `pl_db_version` と `PL_VERSION` が異なれば `PL_DB_Install::activate()` を再実行（テーブル作成/更新・不足設定の補完。ルールは既に1件でもあれば再投入しない）。
- **祝日の自動更新**：毎年4月1日 0:00 に WP-Cron で `PL_Holiday::fetch_and_cache` を実行する想定（注意点は 09 を参照）。

## 7. 技術的な作り（エンジニア向け）

- すべての画面は WordPress 管理画面内。データ取得・登録は `admin-ajax.php` 経由の AJAX（nonce と権限チェックあり）。
- DBアクセスは `$wpdb`（プレースホルダ使用）。テーブル接頭辞は `{$wpdb->prefix}paidleave_*`。
- 社員情報は `employee-manager` の公開関数のみ経由（直接DBは見ない。ただし申請一覧の氏名取得だけ `emp_master` を JOIN している）。
- フロントは jQuery のみ。`admin.js` は画面ごとに `if ($('#pl-xxx-page').length)` で処理を切り替える。
- JS へは `wp_localize_script` で `plData`（AJAX URL、各 nonce、各画面URL、未処理申請件数）を渡す。
- 日付は PHP の `date()` / `DateTime` で処理（サーバーのタイムゾーン設定に依存）。
