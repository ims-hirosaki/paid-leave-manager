# 05 データモデル

DB：WordPress の MySQL/MariaDB。テーブル接頭辞 `{prefix}`（通常 `wp_`）。作成・更新は `dbDelta()`（`PL_DB_Install::create_tables`）。
**外部キー制約は張っていない**（アプリ側で整合性を保つ）。文字コードは `$wpdb->get_charset_collate()`。

## ER 概要

```
(employee-manager: emp_master) ── employee_code ──┬── paidleave_grants ──(grant_id)── paidleave_consumptions
        （外部・参照のみ）                         ├── paidleave_consumptions (employee_code も保持)
                                                   └── paidleave_requests
paidleave_rules / paidleave_settings / paidleave_holidays  … 独立（マスタ・設定）
```
- 社員との関連は**社員コード（文字列）**。社員マスタ側の更新（コード変更・削除）に追従しない。
- 付与1:消化N。1回の消化が複数付与にまたがると**同じ日付の消化レコードが複数行**できる。

---

## T1 `paidleave_rules`（付与日数ルール）

| カラム | 型 | 説明 |
|---|---|---|
| id | INT UNSIGNED AI PK | |
| tenure_months | SMALLINT | 勤続月数の区分（6/18/30/42/54/66/78） |
| weekly_days | TINYINT | 週勤務日数（1〜6） |
| granted_days | DECIMAL(4,1) | 付与日数 |
| effective_date | DATE | 適用開始日 |
| created_at / updated_at | DATETIME | 自動 |

UNIQUE：`(tenure_months, weekly_days, effective_date)`。同じ区分でも適用日違いで履歴として複数保持でき、参照時は「適用日 ≦ 基準日で最新」を採用。
初期投入：テーブルが空のときだけ投入。7区分 × 5系列（週6・4・3・2・1）＝**35件**。**週5の行は無い**。ルール設定画面で保存すると 7×6＝42セルすべてが保存される。

## T2 `paidleave_settings`（設定：キー・バリュー）

| カラム | 型 | 説明 |
|---|---|---|
| id | INT PK | |
| setting_key | VARCHAR(50) UNIQUE | キー |
| setting_value | VARCHAR(500) | 値（文字列。配列はJSON） |
| updated_at | DATETIME | |

| キー | 初期値 | 意味 | 実際に使われているか |
|---|---|---|---|
| expiration_years | `2` | 有効期限の年数 | ✅ 付与登録・CSV取込 |
| consumption_units | `["1.0"]` | 許可する消化日数（JSON配列） | ✅ 消化チェック・画面セレクト |
| legal_holiday_dow | `[0]` | 休日の曜日（0=日〜6=土） | ✅ 休日判定 |
| use_national_holidays | `1` | 祝日を休日扱いにするか（'1'/'0'） | ✅ 休日判定 |
| rules_effective_date | インストール日 | ルール適用開始日の初期表示 | ✅ 画面表示のみ |
| carryover_years | `2` | 繰り越し可能年数 | ❌ 保存のみで未使用 |
| min_annual_days | `5` | 年間最低取得日数 | ❌ 保存のみで未使用（アラートは5日固定） |
| default_consumption_unit | `1.0` | 既定の消化単位 | ❌ 未使用 |

初期設定は**キーが無い場合のみ**追加（既存値は上書きしない）。保存は `INSERT … ON DUPLICATE KEY UPDATE`。
注意：`rules_effective_date` はルール設定画面の「保存」では更新されない（保存時の適用日は T1 の `effective_date` に使われるのみ）。

## T3 `paidleave_grants`（付与ログ）

| カラム | 型 | 説明 |
|---|---|---|
| id | INT UNSIGNED AI PK | 付与ID |
| employee_code | VARCHAR(20) | 社員コード（INDEX） |
| tenure_months | SMALLINT | 付与時の勤続月数 |
| weekly_work_days_at_grant | TINYINT（既定5） | 付与時の週勤務日数 |
| grant_date | DATE | 付与日（有給発生日） |
| expiry_date | DATE | 有効期限（INDEX）＝付与日＋N年−1日 |
| granted_days | DECIMAL(4,1) | 付与日数 |
| remaining_days | DECIMAL(4,1) | 残日数（消化で減算。失効で0） |
| is_expired | TINYINT(1) 既定0 | 失効フラグ |
| created_at / updated_at | DATETIME | |

- 一意制約は無い。CSV取込は「社員コード＋付与日」で重複判定するが、画面登録では判定しない。
- `remaining_days` は**キャッシュ的な値**。消化ログから再計算する処理は無く、失効・インポート・手動操作でずれる可能性がある（09）。

## T4 `paidleave_consumptions`（消化ログ）

| カラム | 型 | 説明 |
|---|---|---|
| id | INT UNSIGNED AI PK | |
| grant_id | INT UNSIGNED | 充当した付与ID（INDEX）。T3.id |
| employee_code | VARCHAR(20) | 社員コード（INDEX） |
| consumed_date | DATE | 消化日 |
| consumed_days | DECIMAL(5,2) | この付与から充てた日数 |
| unit_type | VARCHAR(10) 既定'day' | `day` / `half_day` / `hour`（現状は `day` のみ使用） |
| note | VARCHAR(255) NULL | 備考（申請受理：「有給申請受理（申請ID: ◯）」、CSV：「履歴インポート」） |
| created_at / updated_at | DATETIME | |

## T6 `paidleave_requests`（有給申請：MAT連携）

| カラム | 型 | 説明 |
|---|---|---|
| id | INT UNSIGNED AI PK | 申請ID |
| employee_code | VARCHAR(20) | 社員コード（INDEX） |
| request_date | DATE | 有給希望日（INDEX） |
| status | VARCHAR(20) 既定'pending' | `pending` / `approved` / `rejected`（INDEX） |
| note | VARCHAR(255) NULL | 申請備考（MAT連携では空） |
| admin_note | VARCHAR(255) NULL | 管理者コメント |
| approved_by | VARCHAR(100) NULL | 受理/却下した管理者の表示名 |
| approved_at | DATETIME NULL | 受理/却下日時 |
| created_at / updated_at | DATETIME | |

マイグレーション（`migrate_existing_tables`）：旧版で無かった `admin_note` の追加、`approved_by` が整数型なら VARCHAR(100) に変更。

## 一時データ（transient）
- `pl_import_rows_{ユーザーID}`（付与CSVのプレビュー結果）、`pl_import_consume_rows_{ユーザーID}`（消化CSVの社員番号・消化日のみ）。有効期間1時間。本実行後に削除。

## WordPress オプション
- `pl_db_version`：最後に適用したスキーマバージョン（＝`PL_VERSION`）。

## 外部：社員マスタ（employee-manager）の利用項目
`employee_code`（キー）、`name`、`hire_date`、`employment_type`、`weekly_work_days`。申請一覧のみ `{prefix}emp_master` を直接 LEFT JOIN して氏名を取得。

## アンインストール
プラグインを「削除」すると `uninstall.php` が `PL_DB_Install::drop_tables()` を呼ぶが、**`PL_DB_Install` クラスにこのメソッドは定義されていない**（リポジトリ全体を検索しても定義なし）。したがって削除時は致命的エラーになり、テーブルは**削除されない**と考えられる（09 参照）。README の「5テーブルをDROP」は実装と一致しない（実際のテーブルは6つ）。「無効化」ではデータは残る（Cronのみ解除）。
