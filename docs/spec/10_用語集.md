# 10 用語集

| 用語 | 意味 |
|---|---|
| 有給休暇（有給） | 賃金が支払われる年次有給休暇 |
| 付与 / 有給発生 | 社員に有給の日数を新たに与えること。付与した日が「付与日（有給発生日）」 |
| 付与日数 | 1回の付与で与えられる日数（例：10日） |
| 付与ログ | 付与の履歴。1回の付与＝1行（`paidleave_grants`） |
| 消化 / 取得 | 有給を使うこと。使った日が「消化日」 |
| 消化ログ | 消化の履歴（`paidleave_consumptions`）。1回の消化が複数の付与にまたがると複数行になる |
| 残日数 | まだ使える日数。**有効な付与の残りの合計** |
| 有効期限 | 付与日＋有効年数（初期2年）−1日。この日までは使える |
| 失効 | 有効期限を過ぎて使えなくなること。失効した付与は残日数が0になる |
| 失効予告 | 3か月以内に失効する残日数がある状態。一覧・登録画面に警告が出る |
| 有効な付与 | 未失効（`is_expired=0`）かつ有効期限が今日以降の付与 |
| 先入れ先出し（FIFO） | 消化時に**有効期限の近い付与から**順に使うルール |
| 勤続月数 | 入社日からの経過月数（年×12＋月、日は切り捨て） |
| マイルストーン（区分） | 付与日数が変わる勤続月数の節目：6・18・30・42・54・66・78か月 |
| 週勤務日数 | 1週間の所定勤務日数。付与日数ルールの列（週1〜週6） |
| ルール（付与日数ルール） | 「勤続区分×週勤務日数→付与日数」の表。労働基準法の標準が初期値 |
| 適用開始日 | ルールの有効開始日 |
| 消化単位 | 1回の消化で選べる日数（1日、半日0.5など） |
| 法定休日 | 有給を取得できない休日。設定の曜日（初期：日曜）。祝日を含める設定も可 |
| 国民の祝日 | 内閣府公表の祝日。祝日テーブルに保存 |
| 今年（付与起算） | 直近の付与日から1年間（付与日〜翌年の同日の前日）。暦年ではない |
| サイクル | 上記の「今年」の期間（`get_current_cycle`） |
| 現在有効期間内 | 有効な付与だけを対象にした集計の見方 |
| 消化率 | 消化日数÷付与日数×100（画面により分母が違う。03参照） |
| 年5日取得義務 | 年10日以上付与される社員に年5日の取得を義務づける制度。本システムは警告表示のみ |
| 年5日アラート | 今年付与≧10日・今年消化<5日・付与から9か月以降に出る警告 |
| 付与ベース／消化ベース | 集計表の方式。付与ベース＝期間内に付与されたもの、消化ベース＝期間内に消化されたものを対象 |
| 有給申請 | 社員が MAT で保存した有給希望日。状態は 申請中（pending）／受理済み（approved）／却下（rejected） |
| 受理 | 申請を承認すること。同時に消化1日が自動登録される |
| MAT | 勤怠アプリ（my-attendance 系）。有給希望を本システムに送る |
| employee-manager | 社員情報管理プラグイン。社員マスタの提供元 |
| 社員コード | 社員を識別する文字列。すべてのログのキー |
| インポート | CSVで付与・消化履歴を一括登録する機能（プレビュー→本実行の2段階） |
| プレビュー | CSV取込前の確認。DBには登録されない |
| テストデータ削除 | 付与・消化・申請ログの物理削除機能（ルール・祝日は残る） |
| ケイパビリティ（権限） | `access_custom_plugins`（閲覧）、`edit_custom_plugins`（登録）、`manage_custom_plugin_settings`（設定・削除） |
| nonce | AJAX の正当性確認用トークン（WordPress 標準のセキュリティ機構） |
| AJAX | 画面を再読込せずにサーバーと通信する仕組み（`admin-ajax.php`） |
| WP-Cron | WordPress の定期実行機能 |
| transient | WordPress の一時保存データ。CSVプレビュー結果の保持（1時間）に使用 |
| dbDelta | WordPress のテーブル作成・更新用関数 |
