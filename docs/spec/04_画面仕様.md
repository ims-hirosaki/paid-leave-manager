# 04 画面仕様

各画面の構成要素・表示条件・動作・呼び出す AJAX を定義します。ビューは `admin/views/*.php`、動作は `admin/assets/admin.js`。
共通：すべて WordPress 管理画面内（`.wrap.pl-wrap`）。通知は右下のトースト（4秒で消える。成功＝success、失敗＝error）。

---

## S01 従業員一覧（`paid-leave-manager` / `employee-list.php`、ルート要素 `#pl-list-page`）

- **初期表示**：`pl_summary_get`（期間 2000-01-01〜2099-12-31、mode=grant）を呼び、在籍社員の全件を取得して描画。
- **フィルタ**：検索ボックス（氏名・社員コードの部分一致、大文字小文字無視、入力300msデバウンス）。件数表示「◯ 名」。
  - 「在籍中／全員／退職者」のセレクトは**画面上は存在するが、JSで参照されていない**（効果なし。09 参照）。
- **列**：社員コード／氏名／入社日／雇用区分／週勤務日数（「週◯勤務」）／残有給日数／今年の消化／失効予告／有給申請（pending件数の赤バッジ→個人管理へ）／操作（「付与・消化」→`pl-grant-register&code=`、「詳細」→`pl-employee-detail&code=`）
- 空の場合：「該当する社員がいません」。

## S02 付与・消化登録（`pl-grant-register` / `grant-register.php`、`#pl-grant-page`）

| ブロック | 表示条件 | 内容 |
|---|---|---|
| 社員検索 | 常時 | 社員コード入力＋「検索」。`?code=` があれば自動検索。Enter で検索 |
| 社員情報 | 検索成功後 | コード・氏名・入社日・雇用区分・週勤務日数 |
| 有給状況 | 検索成功後 | 1行サマリー（付与累計・消化累計・残・消化率・詳細リンク）。付与なしなら「付与記録がありません」。有効期限3か月以内の付与ごとに警告行。進捗バー（消化済み／残り／消化率） |
| 付与処理（緑） | `check.grantable === true` | 自動判定メッセージ、付与日（初期＝今日）、付与日数（0〜40、0.5刻み、初期＝ルール値）、「付与する」 |
| 消化登録（橙） | 有効残日数 > 0 | 消化日（初期＝今日）、消化日数（セレクト：設定の消化単位）、備考、「消化を登録する」 |

- 検索：`pl_grant_check`（社員存在チェック → 付与可否判定＋サマリー）。失敗時は「社員が見つかりません」等をトースト表示し結果を隠す。
- 付与：確認ダイアログ「◯◯ に ◯日 を付与しますか？」→ `pl_grant_execute`（`tenure_months`・`weekly_days` は検索時の判定値を送る）→ 成功で再検索。
- 消化：確認ダイアログ → `pl_consume_execute`（`mode=single`、`unit_type=day` 固定）→ 成功で再検索。
- 備考：消化日数セレクトは設定に 0.5 があれば表示されるが、同日重複不可のため**同じ日に半日を2回登録することはできない**。

## S03 個人管理（`pl-employee-detail` / `employee-detail.php`、`#pl-detail-page`、メニュー非表示）

URL：`admin.php?page=pl-employee-detail&code=社員コード`。社員が存在しなければ「社員が見つかりません。」

| カード | 内容 |
|---|---|
| 社員情報 | コード・氏名・入社日・勤続期間（◯年◯ヶ月）・雇用区分・週勤務日数、「付与・消化登録へ」 |
| 有給サマリー（現在有効期間内）／今年の消化状況（付与起算） | 03「5」参照。左右2カラム。付与なしなら右側は注意文 |
| 年5日アラート | 条件成立時のみ表示（`#sum-year-alert`）。受理操作後に再描画 |
| 有給申請 | 申請一覧（ID・希望日・申請日時・状態バッジ・申請備考・管理者コメント・操作）。pending件数バッジ「未処理 ◯ 件」。pending行に「✓受理」「✕却下」 |
| 直近の付与 | 最新3件（付与日・勤続・週勤務・付与日数・残・期限・状態：有効/失効）。4件以上で「全付与ログ（◯件）を見る」ドロワー |
| 消化ログ | 件数付きトグルで展開（消化日・日数・備考）。付与との紐づけ（grant_id）は画面に出ない |

**受理・却下モーダル**：ボタン押下でモーダル（受理：「◯◯ の有給申請を受理し、消化登録（1日）を行います。」／却下：「◯◯ の有給申請を却下します。」）。管理者コメント（任意、3行テキスト）。確定で `pl_request_approve` / `pl_request_reject`（nonce は `pl_request_nonce`）を呼び、行・バッジ・コメントをその場で更新、受理時は `pl_grant_get_summary` でサマリーを再取得。完了後に `alert` でメッセージ表示。
- 受理後の「消化ログ」「直近の付与」の表は**自動更新されない**（ページ再読込が必要）。

## S04 集計表（`pl-summary` / `summary.php`、`#pl-summary-page`）

- 条件：期間（初期＝今年の1/1〜12/31）、方式（付与ベース／消化ベース）、「集計する」。
- AJAX：`pl_summary_get`。結果 0 件／失敗：「データがありません」。
- 列：コード／氏名（個人管理リンク）／入社日／有給発生日／付与日数／消化日数／残日数／消化率（<50%：赤、≧80%：緑）。
- 部署・所属の絞り込みはサーバー側（`affiliation_id`, `department_id`）に実装があるが、画面にUIは無い。CSV出力なし。

## S05 有給ルール設定（`pl-rules` / `rules.php`、`#pl-rules-page`、要 `manage_custom_plugin_settings`）

カード構成：①付与日数ルール（7行×6列＝42セル、0〜40、0.5刻み）＋ルール適用開始日 ②有効期限・繰り越し（繰り越し年数 1〜5、消滅年数 1〜5、年間最低取得義務日数 0〜20）③消化単位（1日／半日0.5のチェック）④法定休日（曜日チェック）・国民の祝日トグル・祝日取得ボタン。
- 「ルールを保存する」→ `pl_rules_save`。成功：「ルールを保存しました（◯件）」（件数＝保存したセル数、通常42）。
- 「内閣府CSVから祝日を取得・更新」→ `pl_holiday_fetch`。成功：「祝日データを ◯ 件取得・更新しました」。
- 初期表示の「ルール適用開始日」は設定 `rules_effective_date`（初期＝インストール日）。マトリクスは**今日時点で有効なルール**を表示。
- 注意：適用開始日を**未来日**にして保存すると、その日まで画面のマトリクスには反映されない（今日基準で表示するため）。

## S06 有給インポート（`pl-import` / `import.php`、`#pl-import-page`）

- タブ：付与インポート／消化インポート。
- 流れ：ファイル選択（`.csv,.txt`）→「内容を確認（プレビュー）」→ サマリー表（総行数・空行・有効・エラー・重複 等）／先頭20件サンプル／エラー行表／重複行表 → 「この内容で取込む」／「やり直す」→ 結果表示。
- AJAX：付与＝`pl_import_preview` / `pl_import_execute`、消化＝`pl_consume_import_preview` / `pl_consume_import_execute`（nonce `pl_import_nonce`）。詳細は 06。
- 取込結果：登録件数、重複スキップ件数、失敗件数と明細（付与は有効/失効の内訳、消化は有効付与/失効付与への充当日数の内訳）。

## S07 テストデータ削除（`pl-data-reset` / `data-reset.php`、`#pl-reset-page`、要 `manage_custom_plugin_settings`）

- 警告バナー（物理削除・元に戻せない／削除対象と非対象の明記）。
- 社員別：コード入力→「件数確認」（付与・消化・申請の件数と合計を表示。0件なら削除ボタンは無効）→「この社員のデータを削除する」→確認モーダル→実行。
- 全件：ページ読込時に全体件数を表示 →「全データ削除」→確認モーダル（Esc・外側クリックでキャンセル）→実行。
- 実行後：削除件数の内訳（付与ログ/消化ログ/申請ログ）を表示。

## S08 有給申請管理（`pl-requests` / `requests.php`、**現在は無効**）

- `PL_SHOW_REQUESTS_PAGE = false` の間、メニューにも `pl_request_get_list` AJAX にも登録されない。`true` にすると、状態・希望日の絞り込み付き一覧（最大100件）と受理/却下モーダルが使える想定。
- 注意：`admin.js` の `#pl-requests-page` ブロックは存在しない AJAX（`pl_requests_get`・`pl_request_update`）を呼んでおり、`requests.php` 内の独自スクリプトと別系統の古い実装が混在している。有効化する場合は要確認（09 参照）。

## 共通UI部品
- ボタン：`pl-btn`（primary/success/warning/secondary/danger）、小ボタン `pl-btn-sm`。
- バッジ：`pl-badge`（green=有効/受理、orange=申請中/警告、red=失効/却下）。
- モーダル：`pl-modal-overlay` / `pl-modal-box`。ドロワー：`pl-drawer-toggle`（ID の `Toggle`→`Drawer` で対象を決定）。
- 表示数値整形：`formatDays`（小数1位、末尾 `.0` 省略）。
- XSS対策：JS 側で `escHtml()`、PHP 側で `esc_html` / `esc_attr` を使用。
