# 08 FAQとトラブルシューティング

## A. 利用者向けFAQ

**Q1. 新入社員にいつ有給を付与しますか？画面が自動で付与してくれますか？**
自動では付与されません。入社6か月後以降に「付与・消化登録」で社員を検索すると、付与できる日数が提示されるので、担当者が「付与する」を押します。（一斉付与の機能はありません。）

**Q2. 付与日数はどう決まりますか？**
勤続月数（6/18/30/42/54/66/78か月の区分のうち到達済みの最大）と週勤務日数から、「有給ルール設定」の表で決まります。初期値は労働基準法の標準です。表は変更できます。

**Q3. 有給の期限はいつまでですか？**
初期設定では付与日から2年（付与日＋2年−1日）です。例：2026-04-01付与なら2028-03-31まで。「付与から何年間で消滅するか」で変更できますが、**変更は以後の付与に適用**され、すでに登録済みの付与の期限は変わりません。

**Q4. 期限が切れた有給はどうなりますか？**
管理画面を開いたときに自動で失効扱いになり、残日数が0になります。失効の3か月前から、従業員一覧に「◯日が失効間近」と表示されます。

**Q5. どの有給から使われますか？**
有効期限が近いものから順に使われます（古い付与が先）。

**Q6. 半日休暇は登録できますか？**
「有給ルール設定」の消化単位で「半日単位（0.5日）」にチェックを入れると、消化日数に 0.5 を選べます。ただし**同じ日に登録できるのは1回だけ**のため、午前・午後を別々に登録することはできません。時間単位の有給は未対応です。

**Q7. 土曜日や祝日に有給を取れますか？**
初期設定では日曜日と国民の祝日は取得不可、土曜日は取得可能です。設定は「有給ルール設定」の「法定休日・祝日設定」で変更できます。

**Q8. 間違えて消化を登録してしまいました。取り消せますか？**
画面からの取り消し・修正機能はありません（開発上の今後の課題）。管理者が「テストデータ削除」で社員単位に**全件削除**する方法しかなく、本番ではお勧めできません。システム管理者に相談してください。

**Q9. 間違えて付与を二重に登録しました。**
同上、画面から取り消せません。システム管理者に相談してください。付与前に必ず付与ログで登録済みかを確認してください。

**Q10. 「今年の消化」は1月〜12月ですか？**
いいえ。「直近の付与日から1年間」です（付与日が4月1日なら4/1〜翌3/31）。

**Q11. 「年5日の取得義務」の警告が出ました。**
今年の付与が10日以上あり、今年の消化が5日未満のまま、付与から9か月が経過した（残り3か月未満）状態です。計画的な取得を案内してください。

**Q12. 消化率は何で割っていますか？**
個人管理画面（現在有効期間内）：有効な付与の付与日数に対する、その付与への消化日数。付与・消化登録画面：全付与（失効分も含む）に対する全消化。集計表：期間内の消化÷期間内の付与。画面によって分母が違うので、数値が一致しなくても異常ではありません。

**Q13. 退職した社員は一覧に出ますか？**
在籍中の社員のみ表示されます。退職者の絞り込み切替はまだ機能しません。個人管理画面は URL で直接社員コードを指定すれば開ける可能性があります。

**Q14. 一覧に社員が1人も出ません。**
employee-manager プラグインが無効、または在籍中の社員が登録されていない可能性があります。

**Q15. MAT で申請したのに「有給申請」に出ません。**
次を確認してください。①希望日が休日（日曜・祝日）でないか ②同じ日の申請が既にないか（却下済みの日付なら申請中に戻ります）③社員コードが一致しているか。

## B. エラーメッセージと対処

| メッセージ | 意味・対処 |
|---|---|
| 社員が見つかりません | 社員コードの誤り、または employee-manager 側に登録なし。コードを確認 |
| 入社日が登録されていません | employee-manager で入社日を登録してから再検索 |
| …に対応するルールが見つかりません | 勤続6か月未満、または「週◯勤務」のルールが未設定。ルール設定でその週勤務日数の列に値を入力して保存（特に**週5**） |
| 必須パラメータが不足しています | 付与日数が0以下。0より大きい日数を入力（ルールが0日の場合など） |
| 法定休日（または祝日）には有給休暇を取得できません | 日曜・祝日。別の日を指定。設定で休日曜日を変更可能 |
| ◯ は既に ◯ 日の消化が登録されています | 同じ日付の消化が既にある。個人管理画面の消化ログで確認 |
| 消化単位は 1 日のみ有効です | ルール設定で消化単位を追加した場合のみ他の日数を選べる |
| 残日数（◯日）が不足しています | 有効な有給が足りない。付与済みか、失効していないかを確認 |
| 受理しましたが消化登録に失敗しました | 申請は「受理済み」になったが消化は未登録。付与・消化登録から手動で登録（残日数不足が多い） |
| すでに受理済みです／受理済みの申請は却下できません | 受理後は取り消し不可 |
| 祝日データの取得に失敗しました | サーバーから内閣府サイトに接続できない／mbstring未導入。時間をおいて再実行、サーバー設定を確認 |
| プレビュー結果が見つかりません… | CSVのプレビューから1時間以上経過、または別ユーザーで操作。ファイルを選び直してプレビューから |
| 社員マスタに存在しない社員番号です（CSV） | 社員番号の表記ゆれ（先頭ゼロ・全角など）を確認 |
| 消化日に有効だった付与が見つかりません／残が不足しています（CSV） | 付与CSVを先に取り込む。付与日・有効期限の範囲に消化日が入っているか確認 |
| サーバーエラーが発生しました (HTTP 500) | サーバー側のPHPエラー。エンジニアに連絡（debug.log を確認） |
| 権限がありません。 | アカウントに `access_/edit_/manage_custom_plugin(s)` の権限が無い。ロール管理で付与 |

## C. エンジニア向けトラブルシューティング

| 症状 | 確認ポイント |
|---|---|
| メニューが出ない | ユーザーに `access_custom_plugins` があるか（このプラグインは権限を定義しない）。プラグインが有効か |
| 画面は出るがボタンが効かない／JSエラー | 管理画面ページ判定は `$_GET['page']`。`plData` が出力されているか（`enqueue_assets`）。ブラウザのコンソールを確認 |
| AJAXが `-1` や 403 を返す | nonce 失効（長時間放置）または権限不足。ページを再読込 |
| 残日数が消化ログと合わない | `remaining_days` は付与テーブルに保持する値。失効時に0化、CSVインポートで失効済み付与へ充当した場合は据え置き等でずれ得る。有効付与は `granted_days − SUM(消化)` で検算できる |
| 週5の社員に付与できない | 初期ルールに週5が無い。ルール設定画面で週5列を入力・保存。または週勤務日数が6で登録されているか確認 |
| 付与画面で付与日数が0／空 | ルール行が 0日で保存されている（週5列未入力のまま保存した等） |
| 祝日が反映されない | 祝日テーブル（`paidleave_holidays`）にその年があるか。ルール設定画面で手動取得。`use_national_holidays` が '1' か |
| 祝日の自動更新が動かない | Cron の `yearly` 周期が未登録（09 参照）。`wp cron event list` で確認 |
| 失効処理が走らない | 画面を開いたユーザーに `edit_custom_plugins` が必要。`page` が `paid-leave-manager` か `pl-` で始まる画面か |
| 一覧の件数が多くて遅い | 一覧は社員ごとに複数クエリを実行する（N+1）。社員数が多い場合は集計の最適化が必要 |
| プラグイン削除でエラー／テーブルが残る | `uninstall.php` が未定義の `PL_DB_Install::drop_tables()` を呼ぶ（09）。手動で `DROP TABLE` |
| 有効化後にテーブルが無い | `pl_db_version` オプションが現行バージョンと一致していると再作成されない。オプション削除で再実行 |
